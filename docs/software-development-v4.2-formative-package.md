# 软件开发 v4.2：形成性研究执行包

日期：2026-09-12。用途：在当前工程候选上开展下一轮真实形成性，确定是否值得冻结为论文实验。本文不是招募完成、研究审批、预注册或正式采集证明。主合同见 [研究协议](software-product-development-v1-research-protocol-v4.2.md)，实际运行检查见 [实施记录](software-development-v4.2-implementation-status.md)。

## 本轮需要决定什么

本轮首先判断任务、工具和测量是否能承载软件开发领域的问题：参与者能否在稳定产品目标下，使用版本化证据形成范围恰当的处置；增加可选对象访问后，完整 Chat 是否仍是一条可行路径。形成性不以出现预期 B 优势为通过条件，不按观察到的界面效应调整材料。

当前候选实施由预先实现的有限状态变换组成；Agent 根据自然语言提出受控操作，参与者核对后执行。它没有生成并评测任意源代码补丁。论文方法必须公开这一限制，不能把本实验写成任意仓库中的自动软件修复。

## 主持人可以直接使用的说明

> 你将接手一个已进行一部分的阅读清单产品。历史对话中的用户是场景角色，接下来由你判断需要了解什么以及怎样处理。请使用当前界面向 Agent 提问、核对资料，必要时提出支持范围内的产品操作。你可以保留当前版本、暂不采用候选，或说明还缺什么。这里没有指定必须采用的产品方向。所有产品使用记录均为构造的研究情境，与你在本次研究中的真实交互记录分开。

> 进入任务前，请用自己的话说明产品目标、条目身份、集合归属、待处理状态，以及检查回执能支持什么。仍不清楚时可以继续问。后续每次作出判断时，请记录你的依据和接受范围；你可以继续查询并修订，最后明确结束这一项。

主持人不提示对象数量、应点的节点、C1 缺陷、C2 路径或正确结论。参与者遇到超出支持面的请求时，记录原文和受到的阻碍；不引导其改走作者预设方案以获得“成功”。技术失败单独记录。

## 分开进行的三个环节

| 环节 | 要收集的原始材料 | 本环节的决定 |
| --- | --- | --- |
| 接管理解与界面熟悉化 | 本人解释、追问、纠正记录；既有软件经验；工具理解困难 | 共同目标和概念是否可理解；哪些表述需修改。不能以字数或一次 Agent 回复代替理解判定。 |
| 四个共同机会 | 完整请求/回答、明确判断、当时披露资料、版本和技术中断 | 目标是否清晰；普通与异常材料是否同样可达；合理保留/暂缓是否受阻；任务间是否出现可解释学习。 |
| 开放开发与回顾 | 自发请求、准备/确认/执行、候选与回执、原始理由及回访 | 支持范围是否过窄；是否把有限变换误认为任意开发；何时信息改变了参与者显式表达的判断或请求。 |

形成性可采用边做边说来发现问题；正式计时若不采用边做边说，不得把两种时长混合。访谈中的事后解释只能支持回顾性陈述，不能反推精确的内部意图形成时刻。

## 界面熟悉化与公平性

当前工程预览的共同接管使用无对象 Chat。这能在分配前保留相同内容，但 B 的首次对象接触仍包含发现与学习成本。因此当前可解释对象层的整体初次使用经历，不能称作熟练使用比较。

形成性应先用与正式阅读清单条目、回执和题目独立的练习材料，检验一份固定熟悉化说明。两组练习同样的目标和 Chat 能力；按分配条件说明实际可用功能。B 的对象访问保持可选，不以点击过对象或完成特定路线作为入组、继续或分析条件。练习时间、说明、退出和非采用原样记录。是否采用固定时长或可理解的完成标准，依据形成性后冻结；不按正式条件效果决定。

四共同机会的位置平衡不等于完整携带效应平衡。开放模块发生在共同任务之后，结构学习是该顺序的一部分；如果论文需要未经这些任务训练的开放探索证据，应另设独立形成性样本。

## 评分者材料与校准

使用 [离线审阅流程](software-development-v4.2-review-workflow.md)。每个判断只携带提交时刻之前的可审计材料，原始参与者文字与 Agent 帮助分开呈现。技术状态、有效处置、决定质量分别判断。后续补齐的回执不得反向证明早先判断已充分。

用成对反例校准：准确保留当前版本与空泛拒绝；明确缺失恢复检查的暂缓与已经检查后的错误否认；接受确切版本与沿用旧回执；Agent 建议完整而参与者未作处置；不同措辞的一次复合请求。两位评分者分别编码再处理分歧，保留初始编码与仲裁。新 rubric 的可靠性尚须由真实评分数据检验。

## 冻结前必须由形成性或研究决定补齐的字段

| 字段 | 当前状态 | 冻结依据 |
| --- | --- | --- |
| 参与者来源、资格与样本量 | 未锁定 | 目标人群、真实形成性、可辩护精度或功效依据；不能把模拟画像当样本。 |
| 每机会截止与停止规则 | 未锁定 | 实际可完成性和合理观察窗口；不按正式组间差异挑选。 |
| 正式分配、服务端持久化与中断恢复 | 工程预览不具备正式链 | 分配与完整记录可恢复、跨进程状态一致；过期或丢失明确分类。 |
| 真实 Agent 的固定政策 | 仅接口和受控回放可由工程检查 | 固定模型/参数/工具策略；审阅自然请求、否定、引述、越界和失败；不以 mock 通过代替模型稳定性。 |
| 有效处置与质量编码 | 独立审阅候选 | 校准、可靠性、分歧处理、当时材料充分性。 |
| 主分析与缺失处理 | 协议中的候选 estimand | 分配级分析、参与者聚类、任务权重、截止、区间和缺失敏感性在正式效果可见前确定。 |
| 同意与研究治理 | 本工程包不提供完成证明 | 由实际研究流程落实并记录。 |

## 论文应使用的证据分工

理论与设计：说明稳定目标下的后续重新定位，以及版本化证据和可选对象访问如何实现。工程：报告实际执行的状态、回执、范围失败和恢复测试。形成性：报告真实参与者遇到的问题及修改依据。正式实验：只报告有完整来源、独立编码和冻结分析的实际结果。

模拟窗口中的 20/48、7/48、3/40 或额外检查动作是作者构造刺激的属性，不能填进 A/B 人效结果。零效应、负效应、不使用对象、保留 R0 和超出支持面都必须能进入最终报告。
