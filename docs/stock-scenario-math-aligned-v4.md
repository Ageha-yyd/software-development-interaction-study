# 股票探索场景与实验剧本 V4｜数学模型对齐候选

> 日期：2026-08-28  
> 状态：历史版本，已被 [V5 风险披露触发版](./stock-scenario-risk-disclosure-v5.md) 替代；保留用于追踪设计变化  
> 研究对象：Chat-only 与 Chat + Object（内嵌可指点对象）两种交互路径
> 配套示意图：[股票探索实验场景示意图 V4](./stock-scenario-diagram-v4.md)

## 1. 这一版到底检验什么

高层任务始终不变：

> 请从三只虚构股票中选择一只，作为你使用这笔模拟资金进一步研究并可能配置的优先候选。系统不会执行真实交易。

实验不是检验“卡片是否比文字好看”，也不是检验一套股票分析系统是否完善。它只检验：

> 当 Agent 的中间输出让新的下层信息需求变得重要时，把输出中的领域对象变成可指点的局部入口，能否在不改变信息宇宙和任务终点的情况下，降低用户从当前输出到相关详情、再到后续提问或判断的交互路径成本。

因此，旧版的 Focus Set、Evidence Set、Strategy 面板、Draft/Diff/Undo、状态看板和专用 Round 页面全部退出核心设计。Chat 仍是主要界面；实验条件只增加“内嵌对象 → Popup → 引用/注释”这一层。

## 2. 数学模型如何落到股票场景

把任务表示为有向信息图：

```text
G = (V, E)
```

- `V` 是可稳定引用的领域对象或局部任务状态，例如 Company、FinancialMetric、Risk/Event、初步候选、更新后的约束和最终理由。
- `E` 是从当前可见状态到下一项相关详情或操作的有效语义转移，例如“看到 BETA 现金流较稳 → 查看其连续为正的周期及限制 → 把它引用到当前比较”。
- 两个条件共享同一个 `G`、同一信息池、同一触发器和同一组可接受终点。
- 条件差异只在实际交互路径 `π_I` 和边成本 `C_I(e)`：Chat-only 通过指代、提问、等待和核对完成一条边；Chat + Object 可通过点击、局部展开和对象绑定动作完成同一条边。
- 目标检验是：在最终任务质量不下降的前提下，Object 路径的局部访问和边遍历成本更低。

## 3. 场景构建

### 3.1 参与者

面向非专业但能理解常见财务词汇的个人投资者。任务使用虚构公司与冻结数据，不提供真实投资建议，也不以未来收益判断参与者是否“选对”。

### 3.2 初始目标

- 模拟资金用于进一步研究并可能配置一只候选股票；
- 初始研究视角约为 12 个月；
- 风险偏好适中；
- 希望兼顾增长和稳定。

### 3.3 为什么具有探索性

三只股票不存在支配性答案：

- ALFA 的增长和流动性较强，但估值、波动和客户集中风险较高；
- BETA 的估值、波动和现金流更稳健，但增长较慢且受周期影响；
- GAMMA 居中，但流动性和负债情况形成约束；
- 三家公司都有看似积极但证据有限的近期事件。

用户在看到中间结果后，可能合理地继续检查估值、风险、流动性、现金流、事件可信度或某家公司，因此下一步不能在任务开始时被完全指定。

### 3.4 输出依赖触发器

参与者形成初步候选后，Chat Lane 中出现统一任务更新：

> 情况发生变化：你半年内可能需要使用这笔资金中的 30%。你希望需要时不至于因为难以成交而无法顺利取出这部分钱，也更担心公司经营突然恶化后造成较大损失。其余资金仍计划从约一年的角度考虑，并不希望完全放弃增长机会。请据此重新检查你刚才的判断，并给出最终候选。

高层目标没有变化，变化的是完成目标时突然变得重要的下层信息需求：短期可变现性、下行风险、经营稳定性，以及仍需保留的增长考虑。

## 4. 两个条件共享的冻结信息图

数字是 Metric 对象的属性，不另拆成对象。每个对象都具有稳定 `object_id`、规范事实、来源、限制说明和允许的局部操作。

| 公司 | 对象（规范事实） |
|---|---|
| ALFA | `A-GROWTH` 营收增长 24%；`A-VALUATION` 市盈率 38×；`A-VOLATILITY` 价格波动高；`A-LIQUIDITY` 成交活跃度高；`A-CONCENTRATION` 最大客户收入占比 42%；`A-WEAKSIGNAL` 签署战略合作意向书，但未披露订单、金额或预计收入 |
| BETA | `B-GROWTH` 营收增长 9%；`B-VALUATION` 市盈率 24×；`B-VOLATILITY` 价格波动低；`B-LIQUIDITY` 成交活跃度中；`B-CASHFLOW` 经营现金流连续 8 个季度为正；`B-CYCLE` 行业周期敏感性较高；`B-WEAKSIGNAL` 启动新客户试点，但未说明付费状态、客户规模或收入贡献 |
| GAMMA | `G-GROWTH` 营收增长 15%；`G-VALUATION` 市盈率 29×；`G-VOLATILITY` 价格波动中；`G-LIQUIDITY` 成交活跃度低；`G-DEBT` 资产负债率 68%；`G-WEAKSIGNAL` 新产品试用反馈好于预期，但未披露数量、订单或实际销售 |

初始 Agent 概览在两个条件中逐字相同，并以普通段落或列表呈现上述对象的摘要。Popup 提供的完整规范详情，在 Chat-only 中也能通过自然语言询问得到。

## 5. 对象与 Popup 的最小规则

符合以下条件的内容才成为可交互对象：

1. 有稳定身份，例如“BETA 的经营现金流”，而不是孤立的“8”；
2. 可以被用户独立指代；
3. 存在可局部揭示的详情或可执行的对象范围动作；
4. 系统能把操作映射回唯一 `object_id`。

Chat + Object 中，对象在 Agent 正常文本中以轻量可点击样式出现。点击后只打开一个紧凑 Popup，包含：

- 对象名称和规范值；
- 数据周期/冻结来源；
- 一条解释或证据限制；
- `引用到当前提问`；
- `添加注释`。

注释绑定 `object_id`。它不会自动改变“策略”或替用户判断重要性；当用户把该对象引用进下一条消息时，模型同时收到规范事实和用户注释。正文中只显示一个小注释标记，不出现侧栏或注释看板。

## 6. 两种实验条件

| 维度 | Chat-only | Chat + Object |
|---|---|---|
| Agent 顶层回答 | 相同文本、顺序和格式 | 相同文本、顺序和格式 |
| 对象详情 | 用户在 Chat 中指明对象并追问 | 点击文本中的对象，在原位 Popup 展开 |
| 对象指代 | 用户重新输入名称或描述上下文 | `引用到当前提问`绑定对象 ID |
| 对象备注 | 用户把备注直接写进 Chat | Popup 中添加对象范围注释，并随引用进入下一条消息 |
| 后续生成 | 同一模型从同一冻结信息池回答 | 同一模型从同一冻结信息池回答 |
| 最终任务 | 相同 | 相同 |

Chat-only 不能被故意排版成文字墙；它保留与处理条件相同的标题、段落、列表、表格或代码样式。唯一操纵是对象是否具有语义点击目标和局部操作。

## 7. 真实模型的边界

这一版允许接入真实大模型，但模型不是事实数据库，也不是实验状态机。

### 固定部分

- 19 个对象及其事实、来源与关系；
- 初始 Agent 概览和中间触发器；
- 对象 ID 解析与 Popup 内容；
- 可接受的最终状态与评分规则；
- 两条件使用的模型版本、系统提示、温度、最大输出长度和等待策略。

### 可生成部分

- 参与者的自由自然语言追问；
- 模型基于当前对话路径组织的解释、比较和澄清；
- 用户引用对象或加入注释后，模型如何把该上下文组织进后续回答。

模型只能引用冻结信息池。Chat-only 的语言指代与 Object 条件传入的对象 ID 最终都解析到同一对象注册表；无法唯一解析时必须澄清，不能猜测。API Key 只保存在服务端。

## 8. 七个语义节点的实验剧本

这里的“节点”是固定的任务骨架，不等于强制相同的 Chat turn 数。自然语言 turn 数本身就是交互路径成本的一部分，不能为了表面对齐而固定。

### S0｜任务入口

参与者可见：

> 请从三只虚构股票中选择一只，作为你使用这笔模拟资金进一步研究并可能配置的优先候选。系统不会执行真实交易。你的初始研究视角约为 12 个月，风险偏好适中，希望兼顾增长和稳定。

用户发送起始请求：

> 请先给我一个三只股票的整体比较，帮助我决定先研究哪一只。

### S1｜共同的初始 Agent 输出

两组显示逐字相同的冻结概览：

> 从当前模拟材料看：ALFA 的营收增长最高（24%），成交也最活跃，但市盈率为 38×、价格波动高，且最大客户贡献 42% 的收入。BETA 的增长较慢（9%），但估值较低、价格波动低，经营现金流已连续 8 个季度为正；需要同时注意其行业周期敏感性。GAMMA 的增长和估值居中，价格波动中等，但成交活跃度较低、资产负债率为 68%。三家公司还各有一条尚未形成明确业绩贡献的积极进展。单凭这份概览还不能确定唯一候选，你可以继续检查任意公司、指标、风险或事件。

Object 条件中，Company、Metric、Risk/Event 是点击目标；Chat-only 中是视觉相同的普通文本。

### S2｜第一次自由探索

参与者根据 S1 自行决定下一步，可检查任意对象或关系。系统不提示“应该看流动性”或“推荐关注”。

- Chat-only：通过自然语言说明对象、问题和所需详情；
- Chat + Object：可以点击对象查看详情、留下对象注释、引用到提问，也始终可以继续使用自然语言。

Agent 使用真实模型回答，但只能消费冻结信息池。允许 1–2 次自然语言往返；Popup 操作不计作 turn，但记作事件。

### S3｜形成初步判断锚点

系统在 Chat 中请求：

> 现在请先说出一只你最想继续研究的股票，并简要说明目前最影响你的两项信息。这个选择不是最终答案。

参与者自由回答。系统只记录候选、被引用事实和理由，不评价对错，也不预告后续变化。

### S4｜输出依赖触发器

在初步判断提交后，统一插入第 3.4 节的资金需求更新，并以其完全进入可见区域的时刻作为主计时起点 `t0`。

此时产生多个合理的下层方向：检查可变现性、检查下行风险、检查经营稳定性、保留增长考虑、核查积极事件的证据限制。系统不指定访问顺序。

### S5｜第二次自由探索与意图调整

参与者重新检查旧输出并决定需要追问什么。允许 1–3 次自然语言往返；用户也可以直接形成结论。

Object 条件可进行典型路径：

```text
点击 BETA 经营现金流
→ Popup 查看完整事实和限制
→ 注释“可支持稳定性，但还要结合周期风险”
→ 引用到当前提问
→ 询问 Agent：结合短期资金需求，BETA 的中等成交活跃度是否构成明显限制？
```

Chat-only 可表达完全相同的语义，但必须在 Chat 中重新指明对象、请求详情并把备注写进消息。

### S6｜Agent 路径条件化回答

Agent 根据实际对话历史、被引用对象和注释生成回答。这里允许两条件产生不同的表层回答和后续路径，因为用户到达模型的上下文不同；但每条事实都必须来自同一对象注册表。

这一步用于观察路径如何影响后续交互，不把“模型回答不同”误写成独立实验操纵。模型输入、检索到的对象 ID、输出和等待时间必须完整记录。

### S7｜最终提交

系统在 Chat 中请求：

> 请给出最终优先候选，并说明：①它如何适配更新后的资金需求；②你重新采用了哪些早期信息；③仍需继续核查的一项风险。你可以维持或改变初步选择。

不设置唯一正确股票。一个可接受终点必须同时满足：

1. 明确回应“30% 资金可能在 6 个月内使用”；
2. 使用至少一项可变现性事实；
3. 使用至少一项经营稳定性或下行风险事实；
4. 没有把其余资金的约 12 个月视角和增长考虑完全删除；
5. 指出所选股票至少一项仍需核查的风险或证据限制；
6. 所引用数值与冻结对象一致。

## 9. 两种典型实现路径

### Chat-only

```text
触发器可见
→ 回找旧输出或重新描述目标对象
→ 组织自然语言问题
→ Agent 解析指代
→ 等待回答
→ 核对返回的事实
→ 在下一条消息中重新组织事实与新需求
→ 最终判断
```

### Chat + Object

```text
触发器可见
→ 点击旧输出中的目标对象
→ Popup 获得局部详情
→ 引用/注释对象
→ 直接在下一条消息中提出关系或判断问题
→ 最终判断
```

两条路径到达相同语义终点；它们不必具有相同 turn 数或动作数。

## 10. 与 Claim 直接对应的最小观察项

### 主要机制指标

- 从 `t0` 到首次访问正确对象的时间；
- 从 `t0` 到获得所需局部详情的时间；
- 每条已评分语义边的自然语言 turn 数；
- 输入字符数与自然语言提交数；
- 重新描述上下文、指代修复、回滚和无关对象访问；
- 实际路径相对最短有效路径的额外步骤。

### 质量护栏

- 最终理由是否满足 S7 的六项可接受终点规则；
- 事实准确性；
- 与更新后约束的一致性；
- 对所选股票的风险/证据限制覆盖。

### 次级主观指标

- 任务负荷；
- 对“我能准确指向所需信息”的感受；
- 对“我能在不重建上下文的情况下继续任务”的感受。

不再使用旧版 Strategy 版本、Evidence Set、新鲜/过期状态或看板操作指标。

## 11. 实现验收边界

1. 页面整体像普通 Coding Agent：历史消息、Agent 输出、输入框；不出现实验专用工作台。
2. 两组初始输出逐字、逐序一致，Chat-only 不是文字墙。
3. Object 条件只增加内嵌点击对象及单个 Popup；无侧边 Dashboard。
4. Popup 内容可在 Chat-only 中通过等价语言请求获得。
5. 引用和注释始终绑定唯一 `object_id`，不自动修改用户目标。
6. 两组共享同一信息池、模型配置、触发器、等待策略和终点评分。
7. 实际自然语言路径保持开放；不得把参与者固定成逐句照抄的剧本。
8. 系统能从日志重建每次对象访问、引用、注释、Chat 指代、模型输入输出和最终状态。

## 12. 相对 V3.3 的关键变化

- 保留：三只股票、19 个冻结对象、中途资金约束变化、初步/最终候选、等信息对照、真实模型可选。
- 删除：独立卡片工作台、Focus/Evidence/Strategy 体系、状态看板、Round 页面、Draft/Diff/Undo 和专用流程闸门。
- 改写：8 个固定页面轮次变成 7 个语义节点；自然语言 turn 数允许因交互路径不同而变化。
- 收紧 Claim：核心是相同信息图上的边成本差异；认知负荷与最终理由质量用于机制解释和质量护栏，不单独扩张为“更好的投资决策系统”。
