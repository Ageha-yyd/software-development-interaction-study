# 软件产品开发实验：用户视角入口 v4.2

更新：2026-09-12。现行设计见 [v4.2 研究协议](software-product-development-v1-research-protocol-v4.2.md)。先做四个隔离共同任务，再进入独立材料的开放开发；当前工程实施状态以本版验证记录为准。下面的三段长对话是 authoring library，不代表首版全部可运行。历史 pilot 快照保持原样。

这份文件只告诉你应该从哪里审阅体验，不再用标准说明替代参与者真正消费的内容。完整对话见 `software-product-development-v1-participant-consumed-script.md`。

## 参与者实际看到的开端

参与者打开的是一段从项目最初想法开始的完整 Chat 历史，不是一条“当前 R0 如下”的交接回复。历史里可以看到用户最初只想做轻量保存，随后真实试用不断暴露保存后返回、重复条目、Inbox、Unsorted、Search、数据迁移、旧链接和可访问性问题；每一项现有语义都来自一轮结果、一次用户纠正或一次明确取舍。

读完既有开发历史后，当前参与者还要在不计时的接管阶段用自己的话复述或追问当前产品；Agent 可以自然纠正，直到共同基础成立，才发布第一条计时结果。因此参与者对 baseline 的理解来自整段共同经历和现场接管，而不是记住一页规则，也不是继承历史角色曾经通过的理解检查。

## 实验真正开始时的最近输出

R0 冻结后，Agent 发布同一份中立的四日使用结果：保存和计划内找回都完成，但跨入口行为、组织时机和情境说明没有集中成一种解释。回复同时自然提及若干新或更新的对象，却不说哪个最重要，也不出现候选功能列表。

这条最近输出会改变哪些问题此刻更醒目，但不会清除前面的项目历史。参与者可能回到旧决定，也可能追新数字、具体条目、长期时间线或证据边界。

## 三段接续不是三个可见选项

审阅稿给出三段彼此隔离、由作者构造的代表性可能接续：

- 一位先注意跨入口状态关系，做到联动候选后又被批量范围错误吸引，随后从 Search-first 边界转向长期情境；
- 一位先注意“保存后何时处理”，先观察 R0，再形成无提醒的手动 Focus，并因“完成是否等于归档”重新检查旧语义；
- 一位认为四日数据不足以改产品，直接追一个月的组织变化、具体案例与反例，最后保留 R0 并写下重新打开条件。

真实参与者只经历自己说出来并实际走出的那条对话。没有人会看到这三条摘要、被要求选 A/B/C，或因为走向不同而失败；这些稿件也不能冒充已经观察到的参与者行为。

## Agent 在体验中的样子

Agent 完整回答当前问题及必要的证据边界；被要求时正常综合、比较或建议，一次可查询多个字段和案例。用户提出模糊方向时，只澄清真正改变实现或验证的歧义。没有询问下一步时，Agent 不必自动提供解释清单、产品方向或调查建议；参与者也可以要求它帮助分析。

深度通过继续追问获得。用户可以从汇总追到 cohort、具体条目、跨版本状态、时间线、原始事件和验证来源，也可以横向把状态、组织、Search、维护、数据和可访问性放进同一次判断。Agent 不在一条回复里摊平全部层级，也不替用户宣布“下一步最值得看什么”。

## A/B 在用户眼中的唯一区别

A 是完整 Chat。B 是完全相同的 Chat，再给已经在对话中自然出现的稳定对象一个可选入口。两边看到相同历史、Agent 文本、证据、操作、产品状态和结果；B 不会提前看到信息，也可以全程不用对象。

当参与者已经决定追某个对象时，B 提供重新定位、版本比较和范围指代的另一条路径。它是否节省成本由参与者数据回答；可能没有收益，也可能促进更多有价值的探索。A 不限制一问一字段，不强制重述完整对象名，不额外加入等待。研究不把点击当作理解，也不预设对象让人更快决定什么重要。

## v4.1 如何成为可检验的经历

共同前史→自然语言接管→R0 观察→自主调查/实施或取证→新结果与旧证据的关系→再判断→明确处置。E0 后最多三个评价输出，不是三轮固定问答；保持 R0、丢弃未采用候选和真实回滚都具有各自含义。证据不足可以暂缓，但需要说明具体缺口。

隔离的共同 Local/Compound 机会先比较相同问题；开放主剧本随后观察不同选择，使用独立条目与材料，并承认共同任务带来的结构学习。共同机会不成为开放剧本内的隐藏必经路线。定向查找另作为边界研究候选，不强加到首版流程。

场景中的 12 个画像、四日/月度观察和候选数字是预先构造的模拟材料。真实实验记录的是当前参与者的时间、请求、状态变更和决定质量。完整底层来源尚未全部冻结，不能将作者对话或工具通过包装成真实参与者证据。

时间上分别记录首次 verified Gold 和参与者显式接受；等待、暂停与失败单列。质量上分别检查产品技术有效性、决定的证据/范围/取舍/一致性/追溯性，以及接受、保留、暂缓或未完成。保留 R0 可以是好的决定，实现通过测试也不自动代表方向合理。

## 当前审阅重点

请直接阅读完整对话并判断：共同前史是否足以让人真正理解 R0；最近输出是否中立而有厚度；参与者是否多次因新对象或旧对象更新而改变当前注意线；未选择的线索是否仍可回访；不同注意线是否能形成合理但不同的项目推进；A/B 的差异是否只发生在同一信息空间的访问和操作路径。
