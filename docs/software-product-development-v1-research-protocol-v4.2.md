# 软件产品开发研究协议 v4.2：论文实验候选

日期：2026-09-12。状态：`design_candidate`，未预注册、未招募、未产生人效结果。本协议是本轮研究设计的唯一现行合同；旧架构保留的信息世界与 authoring library 只在不与本协议冲突时作为内容参考。历史 `pilot-v4` 快照不变。工程完成度见本版实施记录，不能由协议的将来时反推已经实现。

## 1. 要回答的问题与贡献边界

在相同软件开发信息、完整 Chat、Agent 政策和可执行操作之上，增加可选对象访问，是否改变参与者抵达**有依据的有效处置**的概率、时间及决定质量？软件任务是阅读清单 Web App 的状态诊断、版本证据核对与有限产品修订。允许零效应、负效应、B 不用对象，以及花更多时间获得更好的判断。

论文可以保留的理论：高层产品目标稳定时，新输出仍可能改变相关的对象、问题、约束及下一动作；版本化信息图可以表示重新定位、取证、比较和验证的成本。工程贡献是同一信息世界的两种访问路径、版本绑定与可审计处置。理论解释不等于观察到了人的内部意图；对象选择不等于理解；整个对象层的分配效果不能分解为选择、布局、摘要和延迟的单独因果效果。

场景的画像、条目、任务日志与候选评价均为**作者构造的模拟刺激**。研究参与者是在这个软件开发世界中做判断的人。两者的数据目录、时钟、标识及报告用语分开。构造丰富材料的目的在于形成合理的选择与反例，不按预期 A/B 效应挑选或调整材料。

## 2. 设计收敛与模块顺序

1. 共同介绍与练习：完整历史，明确历史角色不是当前参与者；在相同、无对象的界面完成语义接管。理解核对在分配/揭示 A/B 前进行。核对 URL-only、canonical identity、membership 与处理状态正交、当前版本与回执范围。保留原始问答、本人解释、纠正与核对依据，不以关键词命中或一次成功回复冒充理解。工程预览只要求记录本人说明并保留待审状态，尚不执行人工理解资格判定。
2. **共同任务模块先行**：参与者级随机分配 A/B；四个隔离机会各自从固定副本开始。公开任务和结果触发相同，完成谓词与材料不由点击路线决定。共同任务内部做位置平衡，记录 period；当前四序列不称作完整一阶携带效应平衡。
3. **开放开发模块随后**：使用另一项目副本、独立条目和证据，完整 H01–H07→现场 H08→明确 H09→E0 后自由调查、实现或保留。共同任务造成的结构学习属于这个固定顺序的研究条件；开放结果不能代表完全未训练者。若需要独立形成性，则另用样本，不把两类观察混为一项确认性试验。
4. Directed 检索是独立的边界研究候选；第一版主要比较不要求参与者额外做 Directed，也不把它作为教学。其 request/target 必须在结果出现前公开，分析独立。

学习、练习、退出与失败完整可见。B 不使用对象不排除；不按成功、所选产品方向或对象使用筛选主要样本。避免处理后筛选的依据参见 [Montgomery、Nyhan 与 Torres 的原论文](https://cpb-us-e1.wpmucdn.com/sites.dartmouth.edu/dist/5/2293/files/2021/03/post-treatment-bias.pdf)；这里的模块安排是对本研究的设计选择，并非该论文指定的 HCI 流程。

当前预览在共同 Chat 接管后才首次提供对象入口，包含对象发现与学习成本，不称为熟练界面的纯访问成本比较。形成性应检验分配后的独立界面熟悉化：不复用研究题目和数据，两组目标、时间/结束规则相同，使用各自可用界面；B 无须使用对象才能继续或纳入分析。当前四序列独立随机抽取仅保证期望位置平衡；正式分配应在 A/B 内以序列分块并记录实际频数。该程序尚未由浏览器预览实现。具体主持与冻结材料见 [形成性执行包](software-development-v4.2-formative-package.md)。

## 3. A/B 共同合同

| 项目 | 共同要求 |
| --- | --- |
| 信息 | 同一版本、公开任务、Trigger、事实、普通案例、异常案例、来源与未知。未来材料按共同请求和实际状态发布。 |
| Chat | 完整真实历史；支持一次多目标、全部 scoped 资料、比较、综合及被请求的建议。不截断历史后声称完整上下文。达到服务容量时明确报错。 |
| Agent | 同一模型、指令、语义检索和错误策略。条件、选中对象、浮窗状态不注入 Agent；对象问题只在参与者实际发送后成为自然语言请求。 |
| 操作 | 相同 inspect、compare、request evidence、propose、verify、adopt、retain、defer、discard、rollback 语义。B 是可选访问与指代路径。 |
| 揭示 | 检索命中、投喂 Agent、文本提及、详情可见分别记录。不把 packet 中所有节点记为参与者已读。 |
| 终点 | 相同允许处置、事实规则、版本约束与质量 rubric。不奖励某种功能或指定路线。 |
| 延迟 | 原样记录 Chat/本地操作等待；主要效果是整体交互包，等待差不可单独称为指代成本。 |

“可一次取全”指当前合法范围内的信息，不是提前获取尚未执行的候选结果。小范围材料完整交付；超出单次容量的候选原始记录显式分页，每页列出实际条目、总数、未交付数及续页游标，并在同一 Chat 提供完整原文下载。A/B 的分页、下载与完整性规则相同，不把第一页或摘要称作全量交付。达到完整对话容量后显式停止请求，不暗中删除历史。普通案例和异常案例必须使用条件无关的明确选择规则。参与者可以问出作者没写过的措辞；无法解析时澄清，超出评价支持面时记录真实缺口，不静默换成最近剧情。

## 4. 四个共同机会的唯一结构化来源

`scenarios/materials/common-opportunities-v4.2.mjs` 是四机会的公开任务、Trigger、按需事实与技术 Gold 的可执行来源。字段应包含独立 replica、exact revision、来源、允许动作及判定限制；不包含虚构正式样本量或截止时间。

| 机会 | 结果使什么判断变得相关 | 必须避免的捷径 |
| --- | --- | --- |
| COMMON-LOCAL-STATE | 条目在归类后不再出现在 Unsorted；核对 as-of 状态与当前语义 | Trigger 不直接给出全部状态答案；“不知道动机”不能替代实际状态判断。 |
| COMMON-COMPOUND-WL | 联动候选改变范围和状态表达；判断证据是否覆盖待接受状态 | 不能把旧回执用于修改后的状态；也不能要求逐对象访问。 |
| COMMON-LOCAL-PORTABILITY | 导出完成后，需要判断该回执支持什么当前声明 | 只报“成功”不等于绑定了版本和声明范围。 |
| COMMON-COMPOUND-PORTABILITY | 候选同时改变归属/路由；核对迁移、往返与回滚覆盖 | 只认可实际验证的范围；不能把导出通过扩大为整个迁移/回滚通过。 |

技术 Gold 接收结构化决定包，检查事实、版本、scope、实际状态和参与者显式处置；不读取点击路线。不把 Agent 建议当参与者决定，也不把技术 Gold 当自然语言理解或人工决定质量。未实施自然语言到决定包的可靠映射时，保留人工核对状态，不能用局部关键词替代。

所有公开任务都要求“作出范围明确、与证据一致的处置”，同义表达与一次复合请求可以完成。合理暂缓需要实际相关的缺失/冲突/失败、受影响范围、安全保留状态及能解决该缺口的下一检查；空泛“证据总是不够”无效。证据完整时，有依据保留 R0 仍可有效。快速正确处置不惩罚，不设最低时间、轮数或点击数。

共同目标在结果前给出；任务说明不预告结果中的取消范围、过期回执或缺失恢复检查。具体问题在结果与按需材料中出现。这些固定机会仍只能支撑限定的软件证据访问比较，不能独立证明高探索性、内部意图形成或普遍 output-contingent 机制；开放模块中的自发表达变化另作过程证据。

## 5. 开放模块首批支持面

首批只闭合一个有限的软件开发面：R0、联动查看/批量范围候选 C1、一次按证据约束的修订 C2，以及保留 R0、丢弃未采用候选、有依据暂缓。允许跨层查询、旧证据回访和不同取舍，不要求采用或走到 C2。实现具有真实产品状态与受保护行为的候选；使用模拟使用记录说明评价背景，并将其与实际执行的工程检查分开。

| 范围 | 首版处置 |
| --- | --- |
| E0 D4 | 新建可复算的作者构造 ledger；保留完整来源标注，不称“恢复历史原始记录”。 |
| 候选 C1/C2 | 每个版本独立修改说明、实际状态与检查；旧回执不可沿用。使用结果必须绑定本版模拟协议。 |
| O2/O3 / D30 / Focus / Context / pair state | authoring library；只有独立底层包齐备才可发布评价结果。首版不要求覆盖所有组合。 |
| 超出首版支持面 | 记录原始请求与未评价范围，可继续讨论或保留当前状态；不判参与者错误，不给虚构成功。 |

discard = 丢弃未采用候选；retain = 保留当前安全版本；rollback = 从已采用版本执行逆变更并验证恢复。不能把未采用 C1 后保留 R0 写作“回滚成功”。每次采用需要准确 revision、当前检查、明确接受范围和参与者实际确认。没有底层包的长期效果、维护负担和可访问性改善保持 unavailable。

retain 可以保留一个仍未采用的候选，不强迫先 discard；候选归档与当前产品处置分别记录。参与者可以从 R0 直接请求范围明确的修订，不要求先生成或评价有范围问题的联动候选。C1/C2 是模拟窗口中的逻辑候选标识；实际执行版本编号由会话产生，发布评价时明确记录两者映射及准确内容。

当前可执行变换是预先实现的有限内核操作。Agent 选择并提出已支持的变换，参与者审阅后执行；不等同于模型自由编写或评测任意源代码。模拟评价分 W1（独立 R0 与 linked）和 W2（新的匹配 R0 与 scoped），每个 arm 有 12 个隔离副本、72 次保存、48 个找回任务及 40 个批量案例。其原文与内核检查分别标注，跨窗口比较不合并成真实人的效果。较低双入口比例与范围错误、已知标题 Search 的额外导航、显式逐项检查负担并列保留，不能宣称候选全面更好。

## 6. 计时与首要分析候选

主要比较以 A/B **分配**为准，固定四共同机会等权，参与者是独立随机化单位。先并列报告有效处置率、受限制未解决时间及质量估计；没有合理非劣界限和足够精度时，不写“质量不变”。截止时间、样本量、分配分层、区间方法、多重比较及缺失处理在真实形成性与盲态设计后锁定，此处不填猜测数字。

对机会 j 预先固定共同截止 τ(j)，T(i,j) 是从 Trigger 稳定可见到参与者明确作出有效处置的时间：

- `validByDeadline = 1[T <= τ]`。
- `restrictedUnresolvedTime = min(T, τ)`；仅在完整可观察窗口内无有效处置者贡献整个窗口。未完成者的真实完成时间保持空值，不能写成 τ 秒完成。
- 同意撤回、日志丢失、技术中断及不再能观察的主动停止分别标注，不自动编码为确定失败；按冻结的缺失处理与敏感性分析报告。完整观察后的无效处置与缺失不同。

受限时间思路参考 [Royston 与 Parmar 的方法论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC3922847/)。本研究是短时软件任务；不直接移植临床分析模型，也不假设早退独立于条件或结果。

`timeToVerifiedGold` 与 `tExplicitDisposition` 分开。若技术 Gold 已成立但参与者尚未确认，不记完成。合法 defer 记录它自己的有效处置，不伪装为接受产品。`OCFT_acceptance` 只描述接受当前有效结果的子类型；论文主分析不得只留下这类成功者。

所有浏览器事件使用同一单调时钟；记录 Trigger ready/visible、请求开始、响应/事实可见、候选提出、检查完成、显式处置。wall 保留，system waiting 与可验证 pause 另外记录；active 只扣冻结规则允许的区间并集。缺少端点时 unavailable，不倒推。active 不是思考时间。首次可见、可用证据充分与理解不同；没有充分信息集合就不报告 E2。IAR 仅在单位/去重冻结后称信息可用速率。

当前工程流程允许多次“记录当前判断”，继续查询和修订，最后显式结束本任务；每次提交绑定本次 session 与 Trigger 曝光事件。提交的原文与时刻可以供离线独立判定，不需要给参与者透露 Gold。当前尚未执行该判定，待审不等于有效，任何提交时间都不能直接填入 timeToVerifiedGold。最终主动结束而没有有效处置、超时、技术中断和不可观察缺失的区别须按正式协议处理。Trigger 的两帧视口曝光只证明结果元素曾进入可见页面，不证明整段读完或已理解。

NTE 是可选独立预试描述，不是四共同机会的入组、Gold 或计分必备字段。没有独立分布就不计算熵。两个主题下的 Local/Compound 只能支撑限定任务的次要比较；不据此声称普遍复杂度规律。

## 7. 决定质量与可审阅证据

采用证据支持、范围适当、取舍校准、内部一致、可追溯性五个 0/1/2 维度，逐维报告。0 是错误或缺失；1 是部分成立但遗漏重要边界；2 是与可用材料、版本和最终状态充分一致。完整 rubric 与反例见独立设计审阅及架构质量表。它是新编 rubric，尚未验证。

两位独立评分者看统一排版的参与者原文、请求、被请求的 Agent 协助、决定与状态；隐藏条件、对象事件、耗时与界面。Agent 不润色替代原始理由。先以对立案例校准、规定分歧处理，再在真实形成性检查可靠性。技术 oracle 检查状态与工程事实，人工评分评估证据与取舍，两者不相互冒充。

## 8. 分阶段迭代与完成定义

| 阶段 | 产物 | 集中检查及边界 |
| --- | --- | --- |
| 1 设计闭合 | 本协议、四机会、E0 ledger、Agent 公平性修复 | 一轮数据复算、Gold 反例、同请求 parity 和文档冲突检查。只授予设计/材料工程事实。 |
| 2 连续可运行经历 | 候选状态、修订、验证、明确处置和界面接线；旧 E0 可完整回访 | 一轮构建、相关测试及浏览器 A/B 端到端；检查失败、暂缓、非采用、陈旧回执与 B 不用对象。 |
| 3 论文与形成性包 | edit-ready 软件领域方法措辞、证据状态表、操作脚本、盲评包、缺失规则 | 一轮独立审阅；区分已实现、已执行、模拟、待采集。真实形成性/伦理/正式统计计划依赖外部工作。 |

阶段内可以连续编辑；只有形成完整改变后整体检查，有新失败或新实现风险才扩大检查。工程和作者模拟不生成真实参与者效果。达到可运行且证据一致的研究候选后，下一道门是实际形成性与研究冻结，而非继续凭作者直觉堆功能。

## 9. 可直接用于软件领域方法段的英文候选

> We study software-development decisions in a versioned reading-list application scenario. Participants receive the same project history, evidence, agent policy, and semantic operations. The experimental condition adds optional object access to the full chat interface. Four isolated opportunities support comparisons on common tasks; a subsequent open development module examines investigation and disposition within a bounded candidate space. Product-use records are author-constructed stimuli and are distinct from the study participants' interaction records. We will estimate assignment-level differences in valid disposition and time unresolved, and report decision quality separately. This design evaluates the optional object layer as a package and does not directly measure internal intent formation.
