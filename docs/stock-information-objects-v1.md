## 1. 对象模型

每一条固定指标或公司事实都是一个 `Information Object`，具有唯一 `object_id`。Chat + Widget 将其呈现为卡片中的可操作指标行；Chat-only 呈现相同的只读指标行，并通过 Chat 完成语义等价操作。

每个对象最多支持四个用户动作：

| 动作 | 状态含义 | 对 Agent 的影响 |
|---|---|---|
| 了解详情 | 查看固定解释与限制 | 不改变任何状态 |
| 关注 | 加入 Focus Set，供以后重新定位 | Agent可读取，但不自动作为判断依据 |
| 加入依据 | 加入 Confirmed Evidence | Agent后续分析可以消费 |
| 影响策略 | 定位相关 Strategy 字段并形成 Draft | 必须经用户查看 Diff 并确认后才生效 |

状态边界保持为：

```text
查看 ≠ 关注 ≠ 加入依据 ≠ 修改Strategy
```

## 5. 卡片和条件映射

| 界面元素 | Chat-only | Chat + Widget |
|---|---|---|
| Agent文字结论 | 相同 | 相同 |
| 股票卡片标题和指标行 | 相同、只读 | 相同、可指点 |
| 指标值、顺序和详情 | 相同 | 相同 |
| 了解详情 | 在Chat中明确指明对象后获得固定解释 | 点击指标的“了解详情” |
| 关注 | 在Chat中明确说“关注/记住……” | 点击“关注”并进入Focus Set |
| 加入依据 | 在Chat中明确说“把……作为依据” | 点击“加入依据” |
| 影响策略 | 在Chat中描述字段修改，Agent复述后确认 | 打开相关字段形成Draft，查看Diff后确认 |
| 当前Focus/Evidence/Strategy | 通过Chat询问后由Agent按固定顺序复述 | 右侧持久显示 |

不得出现：

- Widget条件独有的指标、详情或解释；
- Agent为Widget条件额外选择或排序“重要指标”；
- 卡片自动推荐关注对象；
- 点击关注或加入依据后自动修改Strategy；
- 通过视觉颜色暗示某个指标是评分真值。

## 6. 与Benefit的覆盖关系

| Benefit | 由哪些对象和操作承载 |
|---|---|
| B1 早期证据再利用 | Round 01—03对象在新需求后被重新查看、关注、加入Evidence，并在最终理由中准确使用 |
| B2a 需求转译 | 指标的“影响策略”只负责定位可能相关的字段；用户仍需自行决定修改值并确认 |
| B2b 共享Intent维护 | Strategy Draft、Diff、Confirmed版本、来源关系与Undo |
| B3 最终判断一致性 | 最终理由是否使用已确认Strategy和相关早期事实形成权衡 |
| B4 风险遗漏 | 最终候选对应的公司特定风险是否被核查或说明 |

## 7. 冻结的动作开放时间

采用分阶段开放：

1. Round 01—03：卡片从第一次出现时即可“了解详情”和“关注”，右侧Focus Set持续保存；
2. 新需求出现后：开放“加入依据”和“影响策略”；
3. 两组从任务开始即采用各自交互方式，并分别记录前期关注成本与新需求后的调整成本。

该方案让Chat + Widget从早期就真实存在，同时避免参与者在新需求出现前提前提交面向未来约束的Evidence或Strategy。后续剧本、界面与日志均以此开放顺序为准。
