# 软件产品开发 v4.1 独立研究设计审阅

审阅日期：2026-09-12。对象：四份现行 `software-product-development-v1-*.md`，不包括 retained pilot 快照。此文件只记录设计建议，没有执行参与者实验、统计分析、runtime 或工程测试。下述方案用于下一版统一协议，不是既有预注册。

## 审阅结论

v4.1 已经给出值得保留的研究骨架：完整 Chat 基线、可选对象层、版本绑定的信息世界、持续的软件开发判断和多种合理处置。当前首要问题是多个旧合同仍可给出不同答案；共同机会、开放任务和完整候选空间同时扩张，尚不能形成一个有限、可复核的研究。下一轮应先确定一个可执行的比较及其边界，再完成支撑它的材料。

建议论文首先检验：在预先指定的软件开发任务机会中，加入可选对象层是否改变到达有效处置的概率与时间。开放开发补充说明参与者如何选择调查、重新解释旧证据和使用两种交互方式。该设计估计对象层整个交互包的效果，不能单凭结果识别选择、摘要、布局、语言理解或延迟中的单独原因。

## 八项优先建议

### P0-1：用一份统一协议替代前置修订与旧章节的冲突

证据：架构开头已修订四共同机会，但 §18 仍让 local Trigger 直接给出需要核对的状态/回执；§18 仍把独立 NTE 作为共同机会入组硬条件；E0 的开放任务仍被登记为围绕 dual-visit 的 common compound anchor。这与前文允许自由调查、NTE 仅作探索、不得预先给答案的合同不一致。

改进：下一版协议只有一个 OpportunitySpec 来源；四共同机会给出完整公开任务、Trigger、按需事实、有效处置、失败和计时定义。旧表删去或明确成为历史说明，不能继续被生成器读取。E0/O1–O3 归入开放模块；NTE 从正式计分的必需依赖删除。没有独立下一步分布时不得报告熵，但无需为检验界面效果强行补造该分布。

### P0-2：共同机会先于开放任务，保持受试者级随机分配

证据：v4.1 计划开放任务先行，随后完成四 anchors。前者在 A/B 中可以造成不同知识、练习量、疲劳与对象熟悉程度，因此后者估计的将是“经历条件化开放任务后”的总效果。现有四条 sequence 平衡位置，但不能称为完整一阶携带效应平衡。

改进：共同机会构成第一模块；开放开发随后使用独立上下文、另一项目副本和不同条目，不能把前一模块答案直接带入。两模块可共享软件领域与产品语义，但需要明确哪些结构能迁移。将模块安排固定为研究的一部分；若希望开放探索完全不受共同任务训练影响，使用独立样本做开放形成性。四机会顺序可做位置平衡并记录 period，不声称“消除了学习”。同一人不跨 A/B，不把多个机会当多个参与者。

### P0-3：先冻结有效处置，再选择统计模型

当前 Gold 过于接近标签：`qualified unknown`、`safe defer` 既可能是正确判断，也可能成为一句“证据不足”的普通过关口令。反过来，要求所有人浏览每条边又会人为制造对象收益。

改进：各任务共同公开需要完成什么判断；Gold 检查事实、版本、范围、实际状态与处置一致性，不检查点击路线、固定表达或作者偏好的功能。为每个机会编写至少一份合法接受/保留/暂缓、一份似是而非的失败与一份单次复合请求即可通过的例子。判定必须对这些例子的同义表达一致。

合法暂缓须满足：确有与拟执行动作相关的缺失、冲突或失败；正确说出受影响范围；当前安全状态可验证；后续信息或检查能够解除所指出的缺口。细节见后文。无需设置最短耗时、固定点击数或强制阅读全部材料。

### P0-4：主要分析包含未成功者和 B 不使用对象者

建议主要比较是四共同机会、所有随机分配者上的分配效果。每个机会设置相同的预先声明截止时间；报告截止时有效处置率，以及受限制的未解决时间。它们可以防止“排除失败者后 B 更快”的偏差。技术无效、主动停止、无效处置与不使用对象分别可见；对象使用与具体路线只进入次要描述。

保留 wall time 作为用户实际代价；system wait 与可观测 pause 另外报告。扣除等待后的结果是另一估计量，不能把它解释为纯思考时间或纯指代效果。开放任务用其 own assignment-level outcomes 与描述性轨迹，不把参与者自选路线拼成同一个时长均值。质量保持需要独立合理的非劣界限；没有界限或精度不足时只报告估计与不确定性。

### P1-5：闭合有界支持面，先不要求所有组合成功

证据：架构 §9 同时规划三类宽候选、多个修订/缩小版本、无提醒版本与三个 pair state；内容库存却仍以 `authoring_pending` 和 `packet_unavailable` 为主。继续补齐全部组合会把一次可发表的机制比较变成无边界产品开发。

改进：定义首批研究支持面：共同机会的四个隔离状态；开放模块的 R0、一个宽候选、一次有依据的修订，以及保留 R0/安全暂缓/丢弃未采用候选。跨问题追问、旧信息回访和变更范围澄清继续自由；不完整的 Focus、Context 或 pair state 作为后续 authoring，不能产生虚构成功回执。超出可评价范围不是错误回答，不按条件替换成最近候选。形成性要检查支持边界是否频繁阻断正常意图；若频繁，缩小公开任务范围或补充最常见缺口，而不是要求参与者猜路线。

### P1-6：模拟记录先成为可复算数据，再生成摘要与对白

证据：库存明确列出 144/72/48、21/27、63 ever-membership 与 D4 57、D30 71、三次 batch 撤销、四次维护等尚待逐案闭合的汇总。现有对白有时仍用“画像属于先归类后处理”解释没有动机说明的 trace。

改进：每个 retained packet 必须有独立记录、明确单位、时间与状态、分子/分母 ID、缺失字段和聚合规则。允许重新设计模拟世界的数值，但新版本必须显式标记人工构造；不得伪装成新增真实观察。不要从汇总反推并宣称“恢复了原始记录”。先核验底层一致，再生成中文摘要；ordinary case 与 exception 采用同一选择规则，A/B 不按难度挑例子。状态组合能够证明正交关系成立，不能证明当事人计划周末处理或已理解界面。

### P1-7：Agent 帮助与自动 oracle 不得把质量变成系统自评

参与者请求建议时应获得完整建议。仍需在决定包区分参与者原始请求、Agent 提议、参与者采用或修改，以及实际状态；不能把精加工后的 Agent 文本当作独立的人类理由。

共同机会的技术 Gold 可以由冻结的状态/事实规则判定；开放产品判断由盲态人工 rubric 另评。评价“证据支持、范围适当、取舍校准、内部一致、可追溯性”，而非字数、对象点击、遵循推荐方案或主动改产品。保留人工原文；向评分者统一排版并去掉条件、界面事件与耗时。先用对立案例校准 rubric，再做真实形成性。oracle、可运行候选和用户研究分别报告，不互相替代。

### P1-8：将论文贡献与设计覆盖对应，避免一次实验承担全部理论

四个任务只有两个主题对，不足以证明复杂度的一般规律；大量对象关系和作者可构造的多条路线也不能证明人的内部意图何时形成。无需为此继续无限增加章节。

主要论文主张限定为这组软件开发机会中的交互包比较。Local/Compound 差异先作候选的次要任务负担比较，明确模板与主题边界；Directed 作为独立边界条件，不能混入同一主时长。开放轨迹中“新的信息出现后参与者明确提出不同问题/改变处置”的事件可支撑过程描述，不能直接等同认知机制被验证。理论保留为可检验解释，工程贡献保留为共享信息、明确版本和对等动作的实现。

## 有效暂缓、缺失与快速结束的具体口径

| 观察到的处置 | 判定原则 |
| --- | --- |
| “先别合并；新取消按钮改变焦点路径，而当前回执只覆盖旧版。保持 R0，补测取消后焦点和剩余范围。” | 若当前材料确实存在这项缺口、任务允许暂缓且 R0 安全，可有效；一次请求或很快完成也不惩罚。 |
| “数据总是不够，先不做。” | 未指出当前任务中的实际缺口及其对下一动作的影响，不匹配有效暂缓；记录不充分处置。 |
| 当前新版所需回执全部有效，但参与者仍称“新版没有验证” | 事实错误，不能用安全措辞获得 Gold。 |
| 证据完整，参与者认为额外维护不值得收益，明确保留 R0 | 若任务允许选择产品方向，理由与材料一致且范围清晰则有效；不能因为未采用作者方案判失败。 |
| 参与者正确指出无法推断画像动机，但未回答任务实际要求的状态/范围判断 | 不自动完成；该未知是否足以阻止拟执行动作取决于公开任务。 |
| Agent 自动给出完整正确建议，参与者未明确处置 | 记录已可用建议/候选 Gold，不记参与者已接受。 |
| 参与者要求全部事实，一次得到材料并正确处置 | 合法 Full Chat 路径；不能再要求逐对象访问或重复证据。 |
| 超出支持面、技术失败、主动停止或撤回 | 分别记录；不得改写为合法暂缓或强行赋予完成时长。 |

防止无依据的“秒退”应靠有效性定义和可靠判定。若 Trigger 本身已经足以作出正确处置，快速结束是有效结果；需要修改的是任务是否仍测试了所需信息访问，而非事后设惩罚。

## 候选首要 estimand 与数据状态

对参与者 i、共同机会 j，令 T(i,j) 为从共同 Trigger 稳定可见到“任务允许的处置经判定有效，且参与者明确作出该处置”的时间；τ(j) 是冻结前确定的机会截止时间。定义：

- `validByDeadline(i,j) = 1[T(i,j) <= τ(j)]`；
- `restrictedUnresolvedTime(i,j) = min(T(i,j), τ(j))`，其中在完整观察窗口内没有达到有效处置者，贡献整个未解决窗口。

主要随机化对比针对 A/B 分配，而非对象使用。以固定、等权的四机会平均为研究任务集合，参与者为独立随机化单位。可预先规定有效处置率不劣作为解释成本收益的条件，同时比较受限制未解决时间；界限必须在见到正式条件效应前得到独立理由。未准备非劣设计时，将有效率、受限制时间和质量维度并列估计，避免宣称“质量保持”。同一参与者的任务不能作为独立样本计算标准误。

这不是把失败者的“真实完成时间”填成 τ。没有完成时间的记录仍为空；τ 仅用于定义上述估计量。实际主动停止时刻、失败类别、观察是否完整另存。因同意撤回、日志丢失或无法继续观察导致的缺失不能自动编码为确定的 τ 失败，应遵从同意与预先规定的缺失处理及敏感性分析。实际样本量、deadline、非劣界限、置信区间方法与模型在形成性和盲态设计后冻结；本审阅没有提供或暗示真实结果。

## 可收敛的两阶段推进

### 阶段 1：形成一个封闭、可审阅的设计包

1. 新版统一协议冻结研究问题、模块安排、首批支持面、A/B 对等原则和首要 estimand 候选；移除旧合同冲突。
2. 四共同机会各完成公开任务、Trigger、独立数据副本、按需资料、合法处置与对立失败样例；两 Directed 另列，不成为主任务前置教学。
3. 开放模块只闭合一个完整连续经历和合法替代处置，并确保普通案例、反例、R0 追问、当前/旧回执、丢弃与保留均可用。
4. 一次阶段性审阅：所有公开数字可由本版模拟记录复算；所有成功文案能找到其状态和证据；同一个语义请求可经完整 Chat 一次实现；Gold 不依赖路径；没有用未知/暂缓口令规避任务。

阶段完成只意味着 `design_candidate + internally_consistent_stimuli`，不意味着实际系统或人效已验证。

### 阶段 2：接线、检验体验并冻结研究

1. 让 runtime 使用同一个协议与材料源，接好状态、对象投影、记录、Gold、显式处置与统一时钟；B 保留不使用对象的自然路径。
2. 完成一轮整体工程/内容检验，重点覆盖一问多事实、跨版本请求、未知/失败、defer、保留、取消与真实非采用；不必每改一段文案就跑全套。
3. 用真实形成性参与者检查理解门、任务难度、支持边界、Agent 代劳、合法终态和评分一致性；作者或模型回放只算工程/authoring 证据。
4. 在查看正式条件效应前据形成性冻结任务包、公开目标、τ、主分析、缺失/退出处理、质量解释和样本量依据；取得实际所需研究审批与同意后才采集正式数据。

阶段 2 中依赖真人与外部决定的部分不能由自主 Agent 合成替代；可先把全部本地可执行工作做到可供形成性使用。
