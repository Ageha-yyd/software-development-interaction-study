# 股票交易辅助场景 Benefit 冻结稿 V1.0

> 状态：已正式冻结；作为剧本修订与 Benefit–Metric 表设计的唯一依据  
> 日期：2026-08-25  
> 确认：用户已于 2026-08-25 确认本版 Benefit  
> 适用场景：面向非专业投资者的虚构股票比较任务  
> 实验对照：Chat-only vs. Chat + Widget

## 1. 与总 Claim 的关系

本场景不修改论文的总 Claim：

> 在多轮、高信息密度的复杂任务中，相比以 Chat 作为唯一交互通道，在 Chat Lane 中嵌入可指点、可操作并能持久呈现任务状态的 Widget，可以降低用户二次消费既有信息和调整任务意图时所需的交互与认知成本，从而提升人机协作效率。

股票场景用于将总 Claim 具体化为两个主 Benefit，以及两个下游的场景性 Benefit。

## 2. 场景前提

参与者已经在多轮对话中阅读了 ALFA、BETA、GAMMA 三只虚构股票的增长、成交活跃度、现金流、估值、负债和业务风险等信息，并形成初步候选。

随后出现中度隐式的新需求：

> 情况发生变化：你半年内可能需要使用这笔资金中的 30%。你希望到时能够较顺利地取出这部分资金，也更担心公司经营突然恶化带来的损失；但其余资金仍计划从较长期角度配置，不希望完全放弃增长机会。请据此重新确认你当前采用的判断策略，并完成最终判断。

该描述不直接告诉参与者应该修改哪些 Strategy 字段。参与者需要自行完成从现实需求到任务 Intent 的转译。

## 3. 主 Benefit B1：约束变化后的早期证据再利用

### 冻结表述

> 当非专业投资者已经阅读多轮股票信息并形成初步候选后，新的资金使用需求会改变早期信息的重要性。相较 Chat-only，Chat + Widget 使用户无需重新组织语言要求 Agent 复述，就能更快重新找到成交活跃度、现金流、增长、负债和业务风险等早期事实，判断哪些信息与新需求相关，并将其明确纳入当前决策依据。

### 具体用户收益

降低用户在目标变化后完成以下过程所需的交互与认知成本：

1. 重新定位早期出现的股票事实；
2. 重新判断事实与新需求的相关性；
3. 将相关事实从“看过的信息”转化为当前判断的确认依据；
4. 让 Agent 在后续分析中只消费用户已经确认的依据。

### 不等同于

- 仅仅更快打开一张卡片；
- Graph 比文字更容易阅读；
- 系统自动替用户挑选相关事实；
- Agent 自动复述所有早期信息。

## 4. 主 Benefit B2：需求转译与共享 Intent 状态维护

B2 是一个主 Benefit，由两个连续但可区分的子过程构成。

### B2a：将中度隐式需求转译为多字段 Intent

#### 冻结表述

> 当投资者面对“半年后可能使用部分资金、希望能顺利取出、担心经营恶化，但不愿完全放弃增长”这一中度隐式需求时，相较 Chat-only，Chat + Widget 通过外化当前策略的字段结构，帮助用户更高效、完整地判断哪些目标应该新增、提高、降低或保持不变，减少 Intent 字段遗漏、错误覆盖和误解。

#### 本场景中的正确转译

| 情境含义 | 目标 Intent 状态 |
|---|---|
| 半年内可能使用 30% 资金 | 新增“30% 资金 / 6 个月”的短期需求 |
| 希望需要时能较顺利取出 | 开始关注可变现性 |
| 更担心经营恶化和明显损失 | 经营稳定性、下行风险提高 |
| 其余资金仍从较长期角度配置 | 总体约 12 个月视角保持不变 |
| 不希望完全放弃增长 | 增长降低为中等优先级，但必须保留 |

#### 具体用户收益

更容易将模糊的现实需求转化为结构完整、语义正确的任务 Intent，而不是简单地把全部投资期限改成 6 个月、遗漏风险字段或完全删除增长目标。

### B2b：维护可检查、可恢复的人机共享 Intent

#### 冻结表述

> 在 Strategy 经过修改、确认和后续证据补充后，相较 Chat-only，Chat + Widget 使用户更容易确认 Agent 当前使用的是哪个 Strategy 版本、哪些字段已经生效、哪些仍是草稿，并能发现错误、撤销修改，减少用户理解的策略与 Agent 实际消费策略之间的不一致。

#### 具体用户收益

降低用户完成以下状态管理所需的交互与认知成本：

1. 查看当前已确认 Strategy；
2. 区分草稿修改和已生效状态；
3. 检查修改是否遗漏或错误覆盖字段；
4. 撤销错误修改；
5. 确认 Agent 后续使用的是最新已确认版本。

### B2 的实验公平性边界

1. 两组看到完全相同的中度隐式需求描述；
2. Widget 只展示字段结构、当前值和修改状态，不推荐正确目标值；
3. 点击或关注股票事实不能自动修改 Strategy；
4. Chat-only Agent 只能复述用户实际提出的修改，不能补齐遗漏字段；
5. 用户提出错误修改时，Agent 只能如实复述并请求确认，不能主动纠正；
6. 两组都只有在用户明确确认后才能提交新 Strategy；
7. Agent 后续只消费已确认 Evidence 和最新确认 Strategy。

## 5. 次级 Benefit B3：最终判断与更新后目标的一致性

### 冻结表述

> 在完成证据再利用和 Intent 调整后，Chat + Widget 有助于非专业投资者在最终理由中同时考虑短期可变现需求、经营稳定性、下行风险和增长保留，并使用与这些目标相匹配的早期证据，而不是继续沿用初步选择时的单一判断标准。

### 具体用户收益

提高最终理由在以下三个方面的一致性和完整性：

1. 与最新确认 Strategy 一致；
2. 使用用户明确确认的早期 Evidence；
3. 明确表达增长、可变现性和稳定性/下行风险之间的权衡。

### 边界

B3 不主张 Widget 帮助参与者“选对股票”。ALFA、BETA、GAMMA 均可成为合理的最终候选；质量取决于理由是否与当前 Intent 和已确认 Evidence 一致。

## 6. 次级 Benefit B4：减少所选股票的关键风险遗漏

### 冻结表述

> 当非专业投资者受到增长、走势或稳定性优势吸引时，Chat + Widget 通过让关键风险事实可以被重新访问并加入依据，降低用户在最终判断中只陈述优势、忽视所选股票特定风险的可能性。

### 本场景中的关键风险

| 最终选择 | 至少一项对应的待核查风险 |
|---|---|
| ALFA | 最大客户收入占比 42%；或高估值带来的下行敏感性 |
| BETA | 行业周期变化可能削弱现金流稳定性 |
| GAMMA | 资产负债率 68%；或低成交活跃度影响可变现性 |

### 边界

B4 是股票场景的下游 Benefit，不进入论文总 Claim。风险遗漏结果不显著，不能单独否定 B1、B2 或总 Claim。

## 7. Benefit 层级冻结

```text
总 Claim：Chat + Widget 降低信息二次消费与 Intent 调整的交互和认知成本
│
├─ 主 Benefit B1
│  目标变化后，更高效地重新定位、识别和激活早期证据
│
├─ 主 Benefit B2
│  ├─ B2a 更高效地把中度隐式需求转译为正确的多字段 Intent
│  └─ B2b 更高效地检查、维护和恢复人机共享 Intent 状态
│
└─ 下游场景性 Benefit
   ├─ B3 最终理由更符合更新后的目标和已确认依据
   └─ B4 更少遗漏所选股票的特定风险
```

## 8. 本文档冻结与未冻结内容

### 本轮拟冻结

- B1、B2 为主 Benefit；
- B2 由 B2a 需求转译和 B2b 状态维护组成；
- B3、B4 为次级、下游和场景性 Benefit；
- 新需求采用中度隐式表述；
- Widget 不推荐正确值，Agent 不补齐或纠正用户 Intent；
- 股票选择本身不设置唯一正确答案。

### 暂不冻结

- 每个 Benefit 的 Primary 和 Secondary Metrics；
- 时间指标的精确定义与统计分析方式；
- 增加后的完整任务轮次数；
- 新增或重新分布的相关信息和干扰信息；
- 最终页面实现与日志字段调整。

上述未冻结内容应以本 Benefit 冻结稿为依据继续设计，不得通过修改 Metric 或剧本反向改变 Benefit 定义。
