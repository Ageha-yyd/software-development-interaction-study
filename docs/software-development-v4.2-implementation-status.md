## 可审阅的入口

- `/study/software-development-v42?preview=1&condition=A&agent=local`：共同接管、四共同机会、独立开放 E0、逐次判断与结束。
- 同一路径 `condition=B`：相同 Chat，可选对象；共同接管仍是无对象的共同界面。
- `/study/software-development-v42/workbench`：研究者六条目实现检查区，包含作者构造的范围缺陷与修订。它不进入参与者信息路径，不泄露解决路线。
- 原 `/` 与 `/study/software-product-development-v1`：保留完整 H01–H09 的 E0 独立走查，使用新版可复算来源。

`agent=local` 是明确的工程检索模式；远程 Agent 的语义稳定性仍需真实配置下单独审阅。现有 URL、分配和日志存储为浏览器预览；不能借命名“study”认定正式采集。

## 后续内部工作与外部证据

本轮本地可执行链已经闭合，产出 [论文 redline 与证据表](software-development-v4.2-manuscript-redline.md)、[离线审阅流程](software-development-v4.2-review-workflow.md)和 [形成性执行包](software-development-v4.2-formative-package.md)。实现检查区保留为研究者入口；参与者只能经实际请求与确认进入受控操作。受支持变换预先实现，不称作开放式代码生成。

当前容量边界：单条 Chat 256,000 字符、完整历史 1,000,000 字符、请求 8 MiB；候选原文页最多 128,000 字符且不截断单条记录。全文另从同一已发布 packet 下载；服务端会话进程内存有效期 4 小时，重启/过期没有自动恢复。局部 local lookup 不解释自然语言产品动作；真实远程模式的语义与工具政策需要配置下审阅。模型故障不静默改用另一回答器。

真正的形成性需要参与者与独立评审：核对接管可理解性、任务是否诱导、支持面是否阻断正常意图、评分是否可靠、合理截止时间与样本量。正式统计计划、同意流程、可靠存储和远程模型条件冻结随后确定。零效应、对象不采用与保留 R0 必须一直是合法结果。
