# 股票探索场景与实验剧本 V5.1｜风险披露触发版（冻结）

> 状态：V5.1 冻结实现合同。它取代本仓库中 V5、V4 与 V3.3 对本场景流程、对象数、终点和计时的旧定义。界面视觉沿用当前 Codex 风格，不新增 Dashboard、策略面板或证据看板。

## 1. 本场景支持什么 Claim

总 Claim 不变：

> 在人与 Agent 交互中，将可指点、可展开、可引用评论的对象融入 Chat Lane 输出，相比 Chat-only 能降低信息访问和后续复用的交互成本，并提升人机交互效率。

股票场景只检验其中一个机制切片：参与者形成初步判断后收到新的风险披露，需要重新访问早期信息、理解新旧信息的关系，并更新最终判断。它不单独证明论文关于所有任务类型、概率分支或复杂度边界的全部主张。

本场景不是比较“难读文字 vs. 漂亮卡片”，也不是评估一个股票投资系统。两条件共享同一信息池、初始措辞、披露、模型配置、提交规则和评分；差异集中在对象是否可直接指点、展开和带评论引用。

## 2. 参与者与任务

- 参与者：有一般财经常识、但不是职业交易员的非专业股民。
- 数据：三只虚构股票 ALFA、BETA、GAMMA；冻结日期为 2025-06-30。
- 用户目标：兼顾增长和稳定，从三只股票中选一只作为进一步研究并可能配置的优先候选。
- 安全边界：系统不会执行真实交易，材料不构成投资建议。

参与者可见任务原文：

> 请从三只虚构股票中选择一只，作为我使用这笔模拟资金进一步研究并可能配置的优先候选。我希望兼顾增长和稳定。系统不会执行真实交易。

任务包含真实探索和不确定性：初始材料没有唯一正确股票；三条新披露都可能改变权衡；最终维持或更换候选都允许，只要理由与冻结材料一致。

## 3. 同一信息宇宙：25 个领域对象

对象资格不是研究者临时挑选“重要词”。一个跨度只有同时满足以下条件才进入 registry：

1. 有稳定且唯一的内部 ID；
2. 有独立、非重复的规范详情；
3. 可在后续对话中被独立指代与复用；
4. 对它执行详情访问或引用评论有明确语义。

普通属性词、连接语、排序、推断和 Agent 建议不是对象。内部 ID 与对象类型只进入日志，不向参与者显示。

### 3.1 Company（3 个）

| ID | 对象 | 触发前概览边界 |
|---|---|---|
| A-COMPANY | ALFA | 增长较高，同时估值、历史波动和客户集中度较高 |
| B-COMPANY | BETA | 增长较慢，估值和历史波动较低，经营现金流为正，同时有行业周期暴露 |
| G-COMPANY | GAMMA | 增长和估值居中，同时资产负债率较高、成交活跃度较低 |

Company 详情在触发前只聚合旧事实，不能出现“最新披露”、BETA 回款不确定性或 GAMMA 再融资不确定性。

### 3.2 Fact（16 个，S1 起可见）

| 公司 | 事实对象 |
|---|---|
| ALFA | 营收增长 24%；市盈率 38×；价格波动高；成交活跃度高；最大客户营收占比约 42% |
| BETA | 营收增长 9%；市盈率 24×；价格波动低；成交活跃度中；经营现金流连续 8 个季度为正；行业周期敏感性较高 |
| GAMMA | 营收增长 15%；市盈率 29×；价格波动中；成交活跃度低；资产负债率 68% |

### 3.3 DisclosureEvent（3 个，S4 起摘要可见）

| ID | 最新披露 |
|---|---|
| A-DISCLOSURE | ALFA 最大客户暂停新增订单，并启动供应商审查 |
| B-DISCLOSURE | BETA 核心客户出现逾期回款，应收账款账龄发生变化 |
| G-DISCLOSURE | GAMMA 未来九个月内有 35% 的有息债务集中到期，再融资尚未落实 |

### 3.4 OpenUncertainty（3 个，按需揭示）

| ID | 未确认事项 | 父事件 |
|---|---|---|
| A-UNCERTAINTY | 客户审查结果及新增订单恢复时间 | A-DISCLOSURE |
| B-UNCERTAINTY | 逾期款项最终回收时间 | B-DISCLOSURE |
| G-UNCERTAINTY | 再融资完成时间与融资条件 | G-DISCLOSURE |

Uncertainty 在风险触发前不可访问。S4 后，它只有在参与者展开父事件详情，或在 Chat 中直接询问对应未确认事项后，才进入该会话的 Evidence Envelope；后续 Agent 回答若实际使用它，Chat + Object 条件会将其自然表述渲染为可点击对象。

## 4. 新旧信息之间的预注册关系

以下关系用于离线评分，不是参与者必须按顺序完成的 Gold path：

| 新披露 | 可合理复用的旧事实示例 | 可接受关系 | 受保护边界 |
|---|---|---|---|
| ALFA 客户暂停订单/审查 | A-CONCENTRATION、A-GROWTH、A-VALUATION | 客户集中使订单暂停对收入和增长预期更重要；高估值可能放大预期变化的影响 | 不能写成既有合同已经终止，或审查必然失败 |
| BETA 回款恶化 | B-CASHFLOW、B-CYCLE、B-GROWTH | 新披露削弱“历史现金流为正”对稳定性的支撑；周期暴露可能增加回款风险的重要性 | 不能写成现金流已经转负或款项一定无法收回 |
| GAMMA 债务集中到期 | G-DEBT、G-LIQUIDITY、G-VALUATION | 高负债与集中到期共同提高融资压力；低成交活跃度不能替代企业偿债证据 | 不能写成已经违约或再融资必然失败 |

允许跨公司比较，也允许参与者建立其他与冻结事实一致的合理关系。不得把“初步候选公司的披露”定义为唯一正确首个目标。

## 5. 两个条件的因果合约

| 维度 | Chat-only | Chat + Object |
|---|---|---|
| 固定 S1/S4 内容、顺序和基础排版 | 相同 | 相同 |
| 自由追问事实池、Evidence Envelope、模型配置 | 相同 | 相同 |
| 合格对象在 Agent 输出中的表述 | 普通文本 | 可点击文本 |
| 获取规范详情 | 在 Chat 中指明对象并追问 | 可在 Chat 中追问，也可点击对象打开单一侧边 Popup |
| 引用对象并添加评论 | 通过自然语言复述/引用 | 在对象卡旁逐项“引用并评论”，随下一条问题提交 |
| 阶段按钮、初步/最终答题卡和评分 | 相同 | 相同 |

两条件的语义不变量是：对同一对象与同一操作，确定性内核返回同一规范详情和同一状态差分。自由路径不同后，模型回答不要求逐字相同；要求相同的是事实宇宙、可见 Evidence Envelope、模型配置和状态规则。

Widget 从 S1 第一条 Agent 输出开始启用，并贯穿每一次自由 API 回答、风险披露和历史消息。不是只在固定轮次或风险触发后临时出现。Chat-only 保持相同可读性，不能被故意做成文字墙。

## 6. LLM 与确定性内核的分工

统一链路：

```text
用户自然表达/对象点击
→ 语义解析（对象、指代、组合请求）
→ 确定性内核校验阶段与可见性
→ 生成 Evidence Envelope
→ DeepSeek 将冻结证据组织成自然回答
→ 校验对象标记后渲染
```

Evidence Envelope 至少含：当前可用对象 ID、规范摘要、已经访问的规范详情、解释边界和用户本轮逐对象评论。每次模型调用记录 Envelope hash。

LLM 可以：理解省略、指代、否定和组合请求；组织真实证据；支持多条合理探索路径；在实际使用对象时输出受校验标记。

LLM 不可以：生成或修改实验事实；知道条件、Gold、评分或阶段名称；推进阶段；决定提交是否通过；改变候选；主动提示唯一下一步；告诉参与者还缺哪个评分字段。

未知、越权或尚未揭示的对象标记必须降级为普通文字；模型材料外的陈述记为 unsupported-output violation，进入离线审计。

## 7. 权威状态机

```text
initial_exploration
  ──点击“形成初步判断”──>
initial_submission
  ──完成固定初步答题卡──>
disclosure_exploration
  ──点击“提交最终判断”──>
final_submission
  ──完成固定最终答题卡；立即停表──>
complete
```

- 两个按钮在两条件中位置、样式和文案相同。
- 点击按钮打开两条件完全相同的紧凑侧边答题卡，不产生 Chat turn；确认前可返回探索，草稿保留。
- 答题卡打开时普通 Composer 暂时禁用；只有正式确认提交才生成一条可回溯的结构化用户消息并推进阶段。
- 普通聊天、对象点击、引用评论、消息关键词和模型输出均不能推进阶段。
- 答题卡只检查必填字段和两项依据是否重复，不在线判断内容质量或股票选择是否正确。
- 第一次正式最终提交立即结束主要计时；之后不进行在线语义纠错或补答循环。

## 8. S0–S7 冻结剧本

S0–S7 是八个语义节点，不是固定八轮。自由探索均为 0–n 条消息；内容密度被设计为一般路径约 6–8 个主要消息事件，但没有机械轮次上限。

### S0｜任务入口

显示第 2 节任务原文。

### S1｜共同初始概览

Agent 自然综合三家公司，暂将 BETA 放在第一顺位，同时说明三者的增长、估值、历史波动、现金流/周期、客户集中或负债权衡。结尾只说：

> 这个排序只是基于当前材料。你可以继续追问其中任何公司或信息，也可以在准备好后形成初步判断。

不得推荐固定核查路径。Chat + Object 从本回答起对所有实际出现且合格的对象提供点击能力。

### S2｜触发前自由探索（0–n）

参与者可询问任意已出现公司或事实，也可直接准备提交。Agent 只使用触发前 Evidence Envelope。

### S3｜显式形成初步判断

参与者点击“形成初步判断”，打开固定答题卡：

- `初步优先候选`：ALFA / BETA / GAMMA，单选且无默认值；
- `与候选直接相关的一项当前依据`：自由文本、必填；
- `另一项当前依据`：自由文本、必填，可来自同一公司或跨公司比较。

答题卡不列出 16 个 Fact、不推荐对象、不预填内容。只检查候选与两个文本字段是否填写、两项依据是否完全相同；“是否确实与候选相关”及依据质量由条件盲法评分者离线编码。成功后冻结原始字段，生成一条只读结构化用户消息并显示中性 Chat 确认。

### S4｜风险披露触发器 `t0`

系统以相同顺序同时显示三条 DisclosureEvent 摘要，随后显示：

> 系统收到以上最新披露。请根据你的判断需要继续研究，并在准备好后更新最终选择。

三条摘要完成渲染时记录 `t0`。不得告诉参与者哪一条最重要、先查哪一条或还缺哪些信息。

### S5｜触发后自由探索（0–n）

参与者可点击或用 Chat 访问任意合理对象，也可以直接准备最终提交。可观察路径包括事件、旧事实、公司、详情和 Uncertainty，但不要求固定顺序。

### S6｜信息复用与关系形成（可发生于任意自由回复）

参与者可在自然语言中建立新旧信息关系；Chat + Object 还可逐对象“引用并评论”。评论是随下一次提问提交的临时上下文，不形成常驻策略、Focus 或 Evidence 看板。

Agent 回答用户实际问题，可纠正与冻结材料直接冲突的事实错误，但不得以“通过标准”口吻主动补齐评分项。

### S7｜显式最终提交

参与者点击“提交最终判断”，打开固定答题卡：

- `最终优先候选`：ALFA / BETA / GAMMA，单选且无默认值；
- `最新披露如何影响了你的判断`：自由文本、必填；
- `目前仍有什么不确定性`：自由文本、必填；若参与者认为没有，可填写“暂无”。

答题卡不要求明确列出旧 Fact、新旧关系或某条 Disclosure，避免把离线评分路径泄露给参与者。第一次确认提交立即停表，系统仅回复“已记录你的最终判断”。不显示是否正确、不要求修改到 Gold、不接受第二次提交改变主要终点。

## 9. 主要观测与离线评分

### 9.1 交互效率

- `OCFT wall time`：`t0` 到第一次正式最终提交的墙钟时间；包含真实模型等待，是参与者实际经历。
- `OCFT active time`：扣除窗口失焦时间的活动时间，用于机制分解。
- `model wait time`：DeepSeek 请求等待时间，单独记录但不从主墙钟结果中事后删除。
- `time to first object-directed action`：`t0` 到首次明确对象点击，或可解析的对象定向 Chat 请求。
- 路径成本：Chat turn、对象动作、输入字符、引用评论、澄清、回退、上下文重建与无关访问。

首次对象记录其 ID、类型和操作表面，不赋予候选绑定的“正确/错误”。若后续保留 reasonable-successor set，只能作为预注册的探索性分析。

固定答题卡会强制补齐字段，因此“是否遗漏提交字段”和“因自然语言格式被拒绝的次数”不再作为界面 Benefit 指标；比较重点仍是探索、再访问、复用与完成成本，以及字段内容的离线语义质量。

### 9.2 离线质量护栏

由不知道实验条件的评分者在任务后统一编码：

- 最终候选与更新后目标的一致性；
- 是否实际使用至少一条新披露；
- 是否复用了 S3 前已经使用的旧 Fact；
- 新旧信息关系是否与冻结材料一致；
- 是否保留相关 OpenUncertainty；
- 是否出现受保护事实错误或 unsupported-output；
- 最终理由整体质量。

第一次最终提交无论质量如何都纳入主分析。不能只分析“答对”或成功完成者，也不能用无显著差异直接宣称质量等价；论文需另行预注册等价/非劣界限。

## 10. 日志

每个事件至少含匿名 session、条件、当前阶段、UTC 时间、会话内单调时间和 payload。记录：

- session、窗口 focus/blur、触发前墙钟/活动时间；
- 两次答题卡打开、取消、字段校验失败、卡片停留时间和原始字段；
- `t0`、对象定向动作、首次对象动作、Popup、详情可见和 payload hash；
- 注释编辑/保存/取消/提交，以及是否同时含旧 Fact 与 Event；
- Chat 消息、字符数、对象解析、澄清、模型请求、延迟、Envelope hash、输出对象和无效标记；
- 第一次最终提交的结构化原文、候选、披露影响、不确定性、维持/切换、OCFT、总墙钟、活动时间和模型等待；
- 离线评分器版本及其各项编码（后续写入，不由在线 Agent 生成）。

同一 episode 内的多条边不能当作独立参与者样本。

## 11. 实现验收

- [ ] 唯一 registry 恰为 25 个对象：3 Company + 16 Fact + 3 Event + 3 Uncertainty。
- [ ] S1 起 Widget 可用，且所有自由 API 回答的合法对象都可点击；Chat-only 同文普通显示。
- [ ] 触发前 Company 详情不泄露回款、再融资或最新披露。
- [ ] Event 与 Uncertainty 在触发前不可访问；父事件详情或触发后直接查询可揭示对应 Uncertainty。
- [ ] 参与者 Popup 不显示内部 ID 或 kind。
- [ ] 只有两个显式按钮能打开相同答题卡；关键词、轮数、模型和对象动作都不能推进阶段。
- [ ] 两条件答题卡的字段、顺序、文案、校验与计时完全相同，不列出事实、不预填答案。
- [ ] 初步答题卡允许第二项依据来自同一公司或跨公司比较，语义质量只做离线编码。
- [ ] 第一次正式最终提交立即停表，只显示中性记录确认；无在线 Gold tutoring。
- [ ] 25 个 Popup 详情只含公司、指标、数值、观察期、披露状态与来源等事实字段，不含“不代表/不等于/不保证”等解释性提示。
- [ ] Chat 与 Object 对同一对象返回相同 Evidence Envelope/state diff。
- [ ] 单一侧边 Popup、逐对象评论、`n 引用`、查看/取消和发送后清空保持有效。
- [ ] 参与者看不到条件切换（研究者 preview 除外），API key 不进入客户端。
- [ ] 构建、测试和定向 lint 通过；本地两个条件 URL 均可响应。

## 12. 解释边界

V5.1 的一个 composite disclosure episode 可以支持本场景中的界面效率、信息再访问和判断修订机制，但不能单独识别论文数学模型中的全部分支概率与复杂度效应。初步候选和依据发生在处理条件已启用之后，是处理后状态；主分析不得把它们当作处理前协变量。论文应将这些边界写清楚，并由其他场景或额外实验覆盖更广的理论主张。
