# 股票决策辅助场景 Demo V1.0

> 状态：第一版定稿  
> 日期：2026-08-23
>
> 后续修订版：[股票决策辅助场景 Demo V2.0](stock-decision-demo-v2.md)

## 1. 研究定位

### 总体 Claim

在多轮、高信息密度的复杂任务中，相比以 Chat 作为唯一交互通道，在 Chat Lane 中嵌入可指点、可操作的 Widget，可以降低既有信息二次消费和用户意图调整的交互成本，从而提升人机协作效率。

股票场景不提出新的主 Claim，而是对总体 Claim 的一种具体实例化。

### 研究重心

- 主要研究：交互效率。
- 次要结果：认知负荷、决策遗漏和控制感。
- 股票场景特有 Benefit：减少关键风险信息遗漏。
- 不研究：股票预测能力、AI 生成 GUI、自动识别 Object。

因果关系为：

```text
Chat + Widget
→ 信息可指点、可复用，意图可直接调整
→ 减少回溯、重述、澄清和对话轮次
→ 交互效率提升
→ 可能进一步降低认知负荷和风险遗漏
```

## 2. 目标用户与任务

目标用户是具备基本股票概念、但不具备专业分析能力的普通投资者。

实验不要求用户执行真实交易，而是完成：

> 在 ALFA、BETA、GAMMA 三只虚构股票中，选择一只值得进一步研究的股票，并提交选择理由和需要继续核查的风险。

所有股票、数据和事件均为虚构且固定，Agent 采用 Mock 模型，保证不同条件下的信息内容一致。

## 3. 信息呈现

### Chat 中的 Graph

两组均看到相同的静态股票走势图。Graph 只展示适合视觉表达的数据，例如：

- 三只候选股票的价格变化；
- 不同时间点的走势；
- 基本的相对波动情况。

Graph 不承载完整估值、现金流、客户集中度等指标面板，也不设置复杂仪表盘。

### 文字信息

具体指标和风险通过自然语言描述：

> ALFA 增长较快，但最大客户贡献了 42% 的收入，目前估值也处于较高区间。BETA 增长较慢，但经营现金流更加稳定。

系统内部将关键事实定义为独立的信息单元：

```text
ALFA / 客户集中度 / 42%
ALFA / 估值 / 较高
BETA / 经营现金流 / 稳定
```

Widget 条件下，这些信息单元以类似百科蓝字的形式成为可指点入口。

## 4. Widget 设计

### 4.1 信息 Popup

点击关键事实后，展开局部信息：

```text
客户集中度

ALFA 最大客户贡献 42% 的收入。

可能含义：
主要客户发生变化时，公司收入可能受到较大影响。

[关注] [添加备注] [加入决策依据] [转为策略条件]
```

Popup 不仅用于“查看更多”，还支持后续信息复用和意图调整。

### 4.2 三种信息状态

| 状态 | 含义 | 对 Agent 的影响 |
|---|---|---|
| Source Information | Agent 已经提供的信息 | 不代表用户意图 |
| Focus & Notes | 用户关注、Highlight 或备注的信息 | Agent 可以读取，但不自动改变策略 |
| Confirmed Evidence / Intent | 用户明确采纳的依据或条件 | 影响 Agent 后续输出 |

因此：

- 点击查看不等于关注；
- Highlight 不等于改变意图；
- 添加备注不等于修改策略；
- 只有明确“加入依据”或“转为策略条件”才会改变共享状态。

### 4.3 共享 Intent 面板

Widget 条件右侧显示：

| 区域 | 内容 |
|---|---|
| Current Intent | 当前目标、期限、风险偏好和策略条件 |
| Focus & Notes | 已关注信息和共享备注 |
| Pending Suggestions | Agent 提出但尚未确认的建议 |
| Recent Change | 最近一次调整、影响结果及 Undo |

Agent 不能静默改变用户意图。所有建议必须由用户确认、编辑或忽略。

## 5. 实验条件

| 功能 | Chat-only | Chat + Widget |
|---|---|---|
| Agent 内容 | 相同 | 相同 |
| 股票走势图 | 相同 | 相同 |
| 文字指标和风险 | 相同 | 相同 |
| 获取信息解释 | 通过 Chat 追问 | 点击信息 Popup |
| 标记信息 | 通过 Chat 说明“记住这一项” | 直接 Highlight |
| 添加备注 | 通过 Chat 重新指明对象 | 在信息旁直接 Annotation |
| 加入决策依据 | 通过 Chat 描述 | 点击“加入决策依据” |
| 修改策略 | 通过 Chat 描述并确认 | 直接编辑或从信息转为条件 |
| 查看当前 Intent | Agent 在 Chat 中总结 | 持续可见的 Intent 面板 |
| 撤销修改 | 通过 Chat 提出 | 直接 Undo |
| Chat 输入 | 支持 | 同样支持 |

Chat-only 不是“纯文字”条件。它可以包含相同图表和信息排版，但所有实质性交互必须通过 Chat 完成。

本实验验证 Chat + Widget 这一整体范式，不分别归因于蓝字显著性、Popup、侧栏或 Undo 中的某一个组件。

## 6. 多轮实验剧本

### 阶段一：建立初始意图

用户希望在三只股票中选择一只进一步研究：

```text
投资期限：约一年
风险偏好：适中
目标：兼顾增长和稳定
```

### 阶段二：初始信息呈现

Agent 输出：

- 三只股票的走势图；
- 增长、估值、现金流和业务风险的文字分析；
- 初始候选判断。

关键风险信息在这个阶段首次出现。

### 阶段三：增加信息密度

用户继续询问财报变化、行业环境和公司事件。早期信息逐渐离开当前视野，形成回溯和二次消费需求。

### 阶段四：意图变化

系统提供新的任务约束：

> 你半年内可能需要使用这笔资金，因此现在更重视稳定性和流动性。

用户需要：

- 修改投资期限和风险偏好；
- 重新使用前面出现的信息；
- 决定哪些信息应成为新的决策依据或策略条件。

### 阶段五：最终判断

用户提交：

- 最值得进一步研究的股票；
- 100—150 字选择理由；
- 至少一项需要继续核查的风险。

完整流程约包含 8—12 轮有效交互。

## 7. Benefit—Mechanism—Metric

| Benefit | Widget 机制 | 主要指标 |
|---|---|---|
| 更高效地获取补充信息 | 点击信息 Popup | 信息访问时间、Chat 轮数、输入字符数 |
| 更高效地复用已有信息 | Highlight、备注、加入依据 | 信息定位时间、复用成功率、指代错误 |
| 更高效地调整用户意图 | Intent 编辑、转为条件、Diff、Undo | 调整时间、意图准确率、澄清次数 |
| 减少风险遗漏 | 风险信息可关注并进入决策依据 | 关键风险遗漏率 |
| 降低认知负荷 | 信息和意图状态外化 | 主观认知负荷、控制感 |

端到端完成时间和用户主动操作时间应分别报告，避免结果仅由预设的 Agent 等待时间造成。

## 8. 研究假设

- **H1：** Chat + Widget 能够减少获取和复用既有信息所需的时间、Chat 轮数和输入字符数。
- **H2：** Chat + Widget 能够降低用户调整意图的交互成本，并提高最终 Intent 状态的准确性。
- **H3：** 在信息内容等价的情况下，Chat + Widget 更有利于使相关信息进入最终决策依据。
- **场景性结果：** Chat + Widget 可能降低关键风险遗漏和主观认知负荷，但不作为总体主 Claim。

## 9. 最终边界

第一版不做：

- 真实股票预测与交易；
- 自动推断用户的 Highlight 含义；
- AI 自动修改用户意图；
- 全量指标仪表盘；
- 复杂对象关系图；
- 完整对话目录；
- AI 动态生成 Widget；
- 各 Widget 组件的消融实验。

## 一句话概括

股票场景通过“蓝字信息 Popup—信息关注与复用—共享 Intent 调整”这条路径，检验 Chat + Widget 是否比 Chat-only 更高效地支持已有信息的二次消费和用户意图改变。
